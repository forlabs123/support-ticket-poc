# TicketFlow — PoC автоматизации поддержки

TicketFlow принимает текстовый тикет, за доли миллисекунды определяет тему и риск, затем либо отвечает на основе проверенной базы знаний, либо передаёт обращение оператору. Новая Alice AI LLM (`aliceai-llm`) используется только для аккуратной переформулировки разрешённого ответа; при любой ошибке система возвращается к тексту базы знаний.

## Быстрый запуск

Требуется Python 3.10+ (проверено на 3.11).

```bash
/usr/local/bin/python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
chmod +x scripts/*.sh
./scripts/run-backend.sh
```

В соседнем терминале:

```bash
./scripts/run-frontend.sh
```

Открыть [http://localhost:5173](http://localhost:5173). Swagger API доступен на [http://localhost:8000/docs](http://localhost:8000/docs).

Для этого рабочего окружения backend автоматически читает `YANDEX_API_KEY_GPT` из `/Users/artem/dev/savenok/back/.env`, не копируя секрет в репозиторий. На другой машине создайте `.env` по [.env.example](.env.example). Без ключа PoC остаётся полностью рабочим: автоответ берётся из базы знаний.

Проверка без UI и тесты:

```bash
.venv/bin/python -m poc.demo
.venv/bin/pytest -q
```

## Два демонстрационных сценария

1. **Happy path:** «Как отменить подписку?» → тема `subscription`, риск `low`, статья `KB-101`, безопасный автоответ. При доступной LLM текст переформулируется, при недоступной — отправляется исходный KB-ответ.
2. **Risky path:** «Аккаунт взломали и украли деньги» → темы безопасности, риск `high`, автоответ отсутствует, тикет направлен в `risk-review`.

Все решения записываются как JSONL в `poc/data/audit.jsonl` и доступны через `GET /api/audit`. Текст хранится только как preview: в production потребуются маскирование PII и политика retention.

## Что реализовано, а что только спроектировано

Реально работают отдельный веб-клиент, REST API, rule-based классификатор риска/темы, in-memory база знаний, Alice AI LLM с timeout/fallback, маршрутизация, аудит и smoke-тесты. [Sequence diagram](architecture/diagram.puml) открывается в PlantUML-плагине IDE или любом PlantUML renderer.

Для production лишь обозначены: очередь событий, асинхронная генерация, промышленная БЗ/RAG, SLA и мониторинг, PII-redaction, дедупликация всплесков, human review и устойчивое audit-хранилище. Эти компоненты намеренно не имитируются большим количеством кода.

## Допущения и ограничения

- Правила покрывают небольшой демонстрационный словарь, а не реальную таксономию поддержки.
- Автоответ возможен только при `low` risk и найденной статье; `medium`, `high` и неизвестные темы всегда эскалируются.
- Лимит 500 мс относится к rule-based routing (`routing_ms`), не к сетевой генерации ответа.
- API синхронный для простоты демо; production-версия публикует задачу генерации в очередь.
- JSONL-аудит подходит для PoC, но не обеспечивает production-доступы, retention и неизменяемость.

## Бизнес-ценность

Система снимает с операторов повторяющиеся низкорисковые вопросы и сокращает первое время ответа. Консервативный risk gate не даёт LLM самостоятельно отвечать по мошенничеству, персональным данным и спорным платежам. Аудит делает каждое решение объяснимым: видны тема, риск, причина, источник ответа и время маршрутизации. Пилот должен подтвердить снижение нагрузки без ухудшения CSAT и роста ошибочных автоответов; критерии подробно описаны в [product.md](product.md).
